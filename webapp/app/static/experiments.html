Research question and target

Given a source TLE, can its orbital information and forecast horizon rank cases where its SGP4 propagated position differs from a later-TLE reference propagated to the same target epoch by more than 1 km?

Both states are propagated with SGP4 to a common target timestamp and compared in the same TEME frame. No frame conversion is needed for that pairwise comparison. Because the reference is another TLE, the target is agreement between element sets rather than independently verified physical error.

The forecast horizon is 6, 12, 24, or 48 hours. Separately, the label builder limits how late the reference TLE may be available after the target time; the baseline cap is 6 hours. Sensitivity scripts vary the error tolerance (0.5, 1, 2, 5 km) and reference delay cap (1, 2, 4, 6 hours).

Nested satellite-and-time holdout

Six outer folds hold out one satellite’s November–December rows. Training uses January–August data from the other five satellites; validation uses September–October data from those satellites. Reference-availability crossings are purged at split boundaries. Model selection, calibration diagnostics, and threshold selection use development data, never the held-out test labels.

Ranking metrics below average over the five folds with both classes; F1 is averaged over all six folds with zero-division handling. Values are macro means from nested_loso_summary.csv.

Purged chronological holdout

Train on January–August, validate on September–October, and test on November–December. The reference-availability purge is applied around boundaries. The test contains 2,595 rows and 418 positives (16.1%). XGBoost and logistic-regression thresholds are selected on validation data; test scores are uncalibrated.

The November–December period was examined during earlier development, so this is not prospective untouched validation. The separation prevents test labels from selecting the final validation threshold in this recorded run.

Calibration diagnostic

Cross-satellite out-of-fold Platt scaling did not improve the nested XGBoost probability metrics: macro Brier score changed from 0.1223 (raw) to 0.1250 (calibrated), and log loss from 0.3855 to 0.3922. A single global calibrator is not treated as a validated deployment probability.

The demo therefore reports a raw model score only. The calibration JSON remains in the app model archive as provenance for the separate artifact; it is not applied.

Sensitivity analyses

Saved legacy analyses vary the error threshold across 0.5, 1, 2, and 5 km and the maximum reference delay across 1, 2, 4, and 6 hours. These earlier pooled-validation runs change the retained population as settings change, so they are descriptive secondary analyses and should not be interpreted as the corrected nested estimates.

See results/experiments/sensitivity/ and the scripts under src/reproducibility/ for the saved tables, figures, and reproduction commands.

Reproduction

From the repository root, create and activate a Python environment, install requirements.txt, and follow the experiment commands in the project README. To run this web prototype:

python -m pip install -r webapp/requirements.txt
python -m uvicorn webapp.app.main:app --host 127.0.0.1 --port 8000

Open http://127.0.0.1:8000/ for the interactive page or http://127.0.0.1:8000/experiments for this report.

Scope and limitations

  • Only six satellites from one year are represented; broader object- and year-level generalization is unknown.
  • The target is a TLE-agreement proxy, not independently measured physical truth.
  • The event rate varies by satellite and the data are imbalanced; pooled performance can differ from satellite-wise performance.
  • The November–December period was examined during previous development, limiting claims of untouched prospective validation.
  • Calibration transfer was not established; no operational threshold or action policy is validated.
  • The live demo's bundled model is a separate prototype artifact and its score must not be reported as one of the paper's test results.

Conclusion: interpret the experiments as an initial evaluation of ranking behavior under defined satellite/time holdouts. They do not establish operational reliability or real-world position-error prediction.

Data and experiment details are documented in the repository README. Check applicable Space-Track terms before redistribution of source data. SGP4 output coordinates displayed in the demo are TEME; no ITRF/earth-fixed conversion is performed.
