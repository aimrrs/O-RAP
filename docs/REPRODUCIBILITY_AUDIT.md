## Audit findings and fixes

- Confirmed the distinction between forecast horizons (6/12/24/48 h) and maximum reference delay (baseline 6 h). The delay is `reference_creation - target_time`, not the forecast horizon.
- Confirmed the six-label exclusion: two unique ISS TLE rows share one source key (`2025-01-25 19:06:24 UTC`, epoch `2025-01-25 04:55:56.509824 UTC`). The two source records yield six labels (two each at 6, 24, and 48 h); the feature builder excludes those six rows rather than arbitrarily matching one TLE.
- Confirmed the input exports identify `TEME` and `UTC`. Source and reference states are generated by SGP4 at the same target time and subtracted directly. No frame conversion is performed; this is coherent for the present data, but only because both vectors share the frame and epoch.
- Traced the final Platt values to per-fold calibration: `run_final_tuned_xgboost.py` fits logistic regression on validation logits and exports each fold's coefficient/intercept. The six-fold experiment has six parameter pairs; they must not be described as a single pooled pair. The separate `run_calibration.py` experiment fits one pooled temporal-validation calibrator (2,011 rows, coefficient 1.262472, intercept -0.720820, C=1e6); its exact parameters and protocol are now saved at `results/experiments/calibration_reproduction/tables/calibration_parameters.json`.
- Clarified the global tuning nuance: validation predictions are pooled across the six LOSO validation folds, so a satellite's validation-period rows can influence global configuration choice via other folds. That satellite's held-out test labels are not used. Final fold calibration and F1 threshold selection use only the other five satellites' validation data.
- Removed embedded Space-Track credentials from the verification, download, and coverage scripts; all now require `SPACE_TRACK_IDENTITY` and `SPACE_TRACK_PASSWORD` in the environment. The old value should be rotated because it was committed in the original Git history.
- Added output-directory overrides for temporal and final LOSO scripts, plus a sensitivity runner and aggregator. Existing `results/tables/` and `results/figures/` were preserved.
- Replaced the empty requirements file with the installed environment's `pip freeze` and expanded `.gitignore` for local environments, caches, secrets, and logs.

## Experiment record

All runs used the project's `venv` (Python 3.14.7; XGBoost 3.4.1; scikit-learn 1.9.1; NumPy 2.5.3; pandas 3.0.5; SciPy 1.18.1; SGP4 2.27; Matplotlib 3.11.2).

- Temporal XGBoost: 12,657 train / 2,011 validation / 2,595 test; training-only F1 threshold 0.66; test ROC-AUC 0.9212, PR-AUC 0.6215, F1 0.5892.
- Final LOSO: selected `strong_regularization`; six held-out satellite folds; mean raw/calibrated ROC-AUC 0.8360/0.8360, PR-AUC 0.3872/0.3872, Brier 0.1128/0.1016, F1 0.2698/0.2452.
- Separate pooled temporal calibration: coefficient 1.262472, intercept -0.720820, fit only on the 2,011 validation rows; saved with metadata and diagnostic tables.
- Threshold sensitivity: 0.5, 1, 2, and 5 km.
- Maximum reference-delay sensitivity: 1, 2, 4, and 6 h.
- Per-case inputs, logs, model tables, configuration rankings, aggregate CSV/JSON, and plot are under `results/experiments/`.

The sensitivity runner regenerates each target from `proxy_error_km`, filters to the requested reference-delay cap, reconstructs source features, rebuilds temporal splits, and repeats the project's pooled validation configuration selection. Per-fold calibration and F1 threshold are based only on non-held-out validation data. No held-out test label is used for a decision.

## Data sharing

Space-Track's current documentation states that redistribution of basic SSA data (including TLEs) has blanket approval conditioned on appropriate citation. The same site also displays user-agreement language about prior express approval for transfers. The README links both pages and advises checking the current account terms before external redistribution. The repository preserves the existing raw data and does not silently remove scientific inputs.
